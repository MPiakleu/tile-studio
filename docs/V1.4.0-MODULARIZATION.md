# Tile Studio 1.4.0 — Editor Modularization

## Scope and compatibility

This is a **source-only** SPFx maintenance update built from Tile Studio 1.3.0. The SharePoint web-part manifest ID, solution ID, feature ID, all five editor tabs, 10 layouts, seven composition templates, published properties, page storage format, Graph permission footprint, and React/SPFx dependency versions remain unchanged. Existing manual content, SharePoint list mapping, custom themes, saved presets and imports remain supported. The solution/feature version is increased to **1.4.0.0**; no list migrations or tenant API-consent changes are required.

## Reliability refinements

1. Local UI rerenders preserve the latest write-through property-pane draft until the host supplies a new configuration object.
2. Site URL edits invalidate pending list loads and connection checks, avoiding stale success messages.
3. Importing invalid JSON clears any previously validated import review; changing pasted JSON also invalidates the previous review.
4. Older asynchronous import file reads cannot replace newer pasted JSON; file reads are invalidated at unmount.
5. Preset export and duplicate-name guards use the most recent configuration draft rather than potentially stale props.

No privileged service calls or new client-side permissions were introduced.

## Production acceptance and rollout

1. In a connected workstation on **Node 22.14+**, run `npm ci`, `npm test`, `npm run package`, and optionally `npm run test:browser` with Playwright browser dependencies installed. Confirm the package at `sharepoint/solution/imberon-tile-studio.sppkg` and absence of lint/compiler warnings.
2. In a staging SharePoint site, upgrade the existing App Catalog Tile Studio solution, not a new app; check there are **no new API permission requests**.
3. Validate an existing page with manual tiles: quick successive edits across Content/Style, move/duplicate/delete, color overrides, undo, and save/publish/reload (especially native Visibility settings).
4. Validate SharePoint lists: load/change site, select list, map fields, retry field discovery and check connection; ensure late responses from previous sources never overwrite the active data.
5. Validate personal and shared presets, export/import, stale file read, cancel/confirm, undo, keyboard tab and focus behavior, high contrast, screen readers, dark mode, and 320/375/390/600/768/1024/1440px containers plus 772×599.
6. Roll back to the saved 1.3.0 `.sppkg` and SharePoint page version if validation fails; maintain an exported configuration backup. Do not uninstall the existing solution to roll back.

**Remaining risks:** Live SharePoint serialization and parent/child render lifecycle cannot be fully simulated offline; real React/Fluent typechecking, performance measurements and tenant security boundaries must be validated in their actual host.

# Tile Studio v1.2.2 — Settings Interaction Deep Dive

**Scope:** Source-based audit of Tile Studio v1.2.1 upgraded to v1.2.2. No production SharePoint settings or permissions were changed. Existing solution, feature, and web-part GUIDs are preserved.

## Executive assessment

The source had genuine interactions that could cause an administrator's selection to appear ineffective, overwrite a separate setting, or remove a useful action. These were not merely cosmetic. This release resolves the confirmed issues listed below. It preserves legacy v1.x configurations and keeps the editor in SharePoint's native property pane.

**Test results:** 77/77 automated tests pass, including 700 renderer-setting combinations (10 layouts × 7 compositions × 5 header modes × 2 arrow modes) and 1,280 responsive-setting combinations, plus preset, import/export, unsafe-data, out-of-order requests, and SharePoint property-pane lifecycle regressions. TypeScript's installed compiler validated pure config/service modules under strict mode and syntax-transpiled all 12 source `.ts`/`.tsx` files without syntax errors.

**What this does not prove:** A successful SPFx/Heft/Webpack production build, browser pixel-perfect rendering, accessibility scans with axe, or tenant-specific saved-page behavior. The npm registry was unreachable from this environment during dependency installation; the final `.sppkg` was therefore **not** generated or asserted to be safe for installation. Execute tenant acceptance tests before release.

## Findings corrected

| Area | Failure before correction | Change in v1.2.2 |
|---|---|---|
| Legacy-versus-new rendering | Changing action radius, styles, typography, or metadata could leave the v1 card renderer active and ignore the change | Advanced design choices activate the composable renderer; legacy defaults retain the original whole-card link |
| Primary actions | Some compositions could have a URL but no visible action | A visible, accessible primary action is supplied when necessary |
| Arrow toggle | `Show link arrows` was ignored in composed cards | Arrow visibility follows the global toggle; disabling an arrow never silently strands a primary destination |
| Header/footer collisions | The same badge/status/action could render multiple times | Duplicated footer elements render only once; badge/status header/body placement takes precedence |
| Headerless badges | `Show badge in header` could prevent a footer badge from appearing when the header is disabled | The badge remains visible in its requested footer slot |
| Categories and eyebrows | When both were enabled, the eyebrow was silently discarded | Both display as a combined label |
| Per-tile icon placement | Hide could still display a category icon; left/right could be ignored by certain templates | Hidden respected, and left/right/top positioning wired to composed templates |
| Mobile decorative images | `Hide decorative images` did not cover composed image/split cards | Composed images now expose the decorative state and use the existing mobile CSS rule |
| Mobile metadata | `Hide metadata` did not cover v1 classic cards | Both card renderers follow the mobile setting |
| Mobile secondary actions | Hiding secondary actions could make a card with no primary destination unusable | Only hide secondary when a valid primary destination exists |
| Mobile action stacking | Hidden secondary actions still triggered stack layout | Stack only when secondary actions remain visible |
| Mobile compact padding | Composed cards always used desktop padding | Composed cards inherit responsive padding unless a tile-specific padding override is present |
| Custom icon and image radius | Some per-tile icon positions/image corners were inconsistent | Added composition attributes and tile-specific image radius selectors |
| Font weight | `800` was offered in the editor but reset during normalization | Normalize, export, import and render accept 800 |
| Inherited per-tile style | Invalid per-tile enum/slot values were replaced by classic defaults, altering inherited section styles | Unsupported per-tile values are omitted instead of overriding valid global settings |
| Layout switches | Selecting a new layout overwrote a deliberately customized minimum height | Preserve custom minimum height; update only a value still equal to its previous layout default |
| Rapid edits | Consecutive editor changes could build from stale props | Use the newest in-memory draft for design, source mappings, tile edits, and saved presets |
| Panel remount/callback | A transient invalid change callback could interrupt editing | Defensive callback fallback and explicit pane host unmount on completion/mode change |
| List-data refresh race | An older failed request could invalidate the cached result of a newer successful refresh | Generation-gated cache invalidation |
| Shared-preset refresh race | An older request could populate the editor after the preset list/tenant source changed | Request generation checks and clearing stale results on source change |
| SharePoint theme updates | Existing property-pane editor could retain previous theme colors until reopened | Rerender active pane after theme change |
| Accessible solid-button contrast | Inherited light themes were evaluated against a hardcoded dark accent | Contrast selection now uses the actual SharePoint accent, when available |

## Expected and intentional interactions

- **Global versus per-tile:** A valid per-tile appearance override takes priority over the web-part-wide design; removing the override restores inheritance.
- **Preset application:** Applying a preset intentionally replaces global design and responsive settings, but preserves tile contents, URLs and list connection.
- **Contextual controls:** Image aspect ratio is meaningful only for image/split layouts; KPI metric size is meaningful in KPI layouts; category options only display when an eligible header is enabled. Changing an unrelated control doesn't invent missing data.
- **Two actions:** Composed cards expose independent links rather than nesting links inside a full-card anchor. The v1 full-card click is preserved only while its legacy presentation remains eligible.
- **Visibility:** Conditional presentation and hiding are never used as an authorization mechanism. Connected SharePoint data remains read-only under the viewer's own SharePoint permissions.
- **Service health:** A missing status never means healthy. This component does not connect to an operational status feed by itself.
- **Accessibility:** Keyboard-visible focus, descriptive link behavior, reduced motion, and safe links are retained, but browser/assistive-technology acceptance is still required.

## Required production acceptance tests

1. Build on Node 22 with `npm ci`, `npm test`, `npm run package`, and review any lint/TypeScript/build diagnostics.
2. Upgrade the current Tile Studio solution in an authorized SharePoint App Catalog; do not remove existing instances. Work first on a draft page.
3. Open an existing saved v1.1/v1.2 page and verify content, all existing links, visual layout, and list sources survive upgrade.
4. Verify SharePoint property-pane persistence after two minutes of continuous editing, switching tabs, adding/editing/duplicating/reordering a card, and closing/reopening the property pane without lost edits.
5. In each of ten layout families, try all seven composition presets at full-width, 2-column, narrow section, and mobile-sized widths; visually inspect wrapping, footer buttons, category icons, image crops, badge/status collisions and focus order.
6. Change `showArrow`, `primaryStyle`, `footerAnchor`, icon position and visibility, mobile secondary-hide and stack controls in different orders. Verify that valid links remain reachable by keyboard.
7. Change a global setting, then override one tile; verify a sibling inherits the global value. Reset override and confirm that inheritance returns.
8. Save/reload/publish and ensure newly added design settings persist; export, import, and recheck two sample configurations.
9. Test light and dark SharePoint themes plus custom accent backgrounds, contrast, Windows forced colors, screen magnification, reduced motion, and keyboard-only navigation.
10. For connected lists, test authorized and unauthorized users, deleted lists, outdated GUIDs, invalid columns, refresh, category filters, duplicate values, and two rapid source changes.

## Known limits and design trade-offs

- The full production build and tenant-level acceptance were unavailable in this session. This release is **source-only** until that validation is complete.
- Not every combination of seven compositions and ten layout shells will be aesthetically desirable. The automated matrix verifies essential action/metadata availability; choose and visually review appropriate presets.
- V1 classic cards are whole-card links; enabling advanced composition/style options switches to independently accessible CTA links. Review card click behavior during rollout.
- Some visual values are intentionally bounded to prevent extreme CSS injection/overflow; color contrast of arbitrary custom colors or translucent overlays is not guaranteed.
- SharePoint supports the latest API permissions and editing permissions, but the final live solution requires tenant-specific security/accessibility QA. No new delegated API scopes were added.

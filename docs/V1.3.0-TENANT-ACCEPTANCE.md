# Tile Studio 1.3.0 — SharePoint staging acceptance checklist

Use a dedicated staging SharePoint page and **two Tile Studio instances**: one with saved 1.2.4 configuration (several tiles, images, presets, list sources) and one new 1.3.0 instance. Run these checks in a target tenant with the signed-in employee/editor contexts that will use the web part.

**Record** date, SPFx package version, tenant/site, browser/device, tester, pass/fail, screenshot or repro for every item. Treat native visibility duplication or lost property changes as a **release blocker**.

## A. Property pane and native SharePoint lifecycle — blocking

- [ ] Open SharePoint **Edit page**, select web part and open the native property pane; confirm exactly one native Visibility group with normal mobile/email controls.
- [ ] Change tile title once; continue changing title, color, radius, links, layout, source and mobile columns for **10 and then 30 edits without closing the pane**. Verify live preview reflects the latest change.
- [ ] Save draft, publish, reload hard, reopen pane; verify the **last** values (not the first only) are saved for content, style, source and mobile overrides.
- [ ] Close/reopen pane during typing; verify no duplicate Visibility group, lost editor tab, dropped text, or cursor jump. Switch between multiple Tile Studio instances and edit again.
- [ ] Change properties and **cancel** page editing; verify neither preview state nor draft is incorrectly persisted. Test page version history restore.
- [ ] Toggle SharePoint built-in mobile/email Visibility controls; save/reload and confirm behavior is preserved.
- [ ] Repeat tests using narrow property pane, SharePoint themes/section backgrounds and page edit-mode transitions.

## B. Card behavior — blocking

- [ ] A classic tile with one link is a single whole-card keyboard/mouse target before/after changing radius, padding, accent, template-derived styles and hover motion.
- [ ] Explicit **Card navigation → Separate action links** creates independent focusable links; **Whole card** uses one anchor when only one destination exists.
- [ ] With two destinations, both actions work even if the secondary button label is blank; no nested anchors and no duplicate tab stops.
- [ ] Primary and secondary new-tab links expose understandable accessible names and hints. Unsafe `javascript:`/network-path URLs remain inert.
- [ ] Missing images, empty metadata, long titles, multiple equal-length fields and status badges do not break card alignment or hide actions unexpectedly.

## C. Data access, privacy, performance — blocking

- [ ] List-backed tiles read using the viewer's delegated SharePoint permissions; test 401/403 access denied, nonexistent list/site and indexed/unindexed filters.
- [ ] Two Tile Studio instances loading the same source do not issue unreasonable bursts. Within each instance, overlapping forced refreshes are coalesced. List refresh and Retry recover from transient 429/503 without unbounded requests.
- [ ] Rapidly switch list source and close the editor; old network responses cannot replace new tiles. Retry after a timeout and after an authorization denial.
- [ ] Newly created instance blocks third-party images by default. Explicit approved exact hostname permits images; an unapproved subdomain stays blocked. Existing instances preserve historical image display until policy is changed.
- [ ] Network monitor shows no app secrets, extra Graph consent prompts, or unnecessary third-party referrer data.

## D. Design, keyboard, accessibility — blocking for public release

- [ ] View tile collections in **320, 375, 390, 600, 768, 1024, 1440px-wide containers** (not just viewports) and a **772×599** viewport. Check no clipped tile actions, dialogs or horizontal scroll and no excessive empty card space.
- [ ] Set two mobile columns at 320px; ensure tiles collapse to a usable one-column width. Check long labels, 200%/400% zoom and font scaling.
- [ ] Navigate all tabs and nested settings using keyboard, including Home/End/arrow keys; settings search jumps to actual fields and opens collapsed advanced groups, returning focus predictably.
- [ ] Import valid configuration: review the replacement summary, Cancel, Confirm and Undo. Verify a malformed or oversized JSON file shows an error without changing content. Delete saved preset then Undo.
- [ ] Run automated axe-core plus manual screen-reader checks for accessible link names, new-tab announcements, dialogs, status labels, contrast, focus trap/restoration and 44px action targets.
- [ ] Check SharePoint dark/light backgrounds, Windows forced-colors, keyboard focus, reduced-motion preferences and user overrides. No visual meaning should depend solely on color or hover.

## E. Release and rollback

- [ ] `npm ci`, `npm test`, `npm run build` and `npm run package` pass on the pinned Node/SPFx stack.
- [ ] Check that the actual `.sppkg` contains version **1.3.0.0**, existing GUIDs, no new application permission request and correct developer metadata.
- [ ] Validate at least one SharePoint list with sparse/malformed data and one large 500–1,000-item input, including paging and throttling.
- [ ] Confirm export and restore of existing 1.2.4 configuration, and retained SharePoint page version / App Catalog rollback package.

**Release decision:** production rollout only when blocking checks are signed off by the owner. Do not assume the offline 98-test suite certifies browser or SharePoint-host behavior.

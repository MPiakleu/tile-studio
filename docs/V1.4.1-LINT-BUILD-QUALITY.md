# Tile Studio 1.4.1 — ESLint repair and mandatory build gates

## Issue and root cause

The v1.4.0 modular editor shipped with six missing explicit return type annotations, one JSX unescaped apostrophe warning, one `null` type warning, and a blocking `no-use-before-define` lint error for an abortable retry timer. The previous offline TypeScript and Node regression tests did not execute the repo's native ESLint 9 configuration or the Heft build. As a result, the source ZIP was handed over without a successful native production build.

## Corrections

- `useEditorDraft.ts`, `useEditorHistory.ts`, `createTileActions.ts`, `useSourceEditor.ts`, `usePresetsEditor.ts`, `useEditorController.ts`: explicit return types using exported, strongly typed interfaces; no broad `any` types or lint suppressions.
- `ContentSection.tsx`: correct JSX entity for the apostrophe in the image privacy hint.
- `services/listData.ts`: avoid reading the backoff timer before declaration. Preserve listener cleanup and cancellation on dispose. Keep the browser `Headers.get()` return signature (`string | null`), with an adjacent, single-line documented lint exception (rather than changing a real platform contract just to satisfy a lint preference).
- Keep existing SharePoint IDs, layouts, editor tabs, configuration format, dependencies and permissions. Increment npm/package-lock/SPFx solution/feature versions to 1.4.1.

## Prevent recurrence

- `npm run lint` executes the project's actual ESLint configuration with `--max-warnings 0`.
- `npm run package` first removes any stale .sppkg, then runs the **real** `npm test`, strict lint, a **clean production Heft build**, Heft package-solution, and a real package existence/ZIP signature check. Every stage must succeed; one warning blocks the release.
- `Build.ps1` delegates to that same gate.
- `.github/workflows/spfx-release-check.yml` executes `npm ci`, `npm run package`, and the existing `tests/verify-package.py` structural/permission audit on every push and pull request. The generated `.sppkg` is uploaded only if all stages pass.
- `tests/release-gates.test.cjs` has three regression tests that protect the strict checks, version alignment and CI contract.

| npm installation / actual ESLint / production Heft / `.sppkg` | **BLOCKED** — `EAI_AGAIN registry.npmjs.org`, then `ENOTCACHED` in offline mode; `npm run package` stops at missing `esbuild` |
| SharePoint tenant and browser validation | **NOT TESTED** |

**The source ZIP is not a verified production package**. It is not safe to claim that all native lint or build failures are resolved until CI or a connected development workstation runs `npm ci && npm run package` successfully. The new source is prepared to enforce that check instead of silently allowing a warning-heavy build.

## Required commands on your workstation

```powershell
npm ci
npm run package
# Optional additional UI checks, if Playwright browsers are installed:
npm run test:browser
```

Then run the [tenant acceptance checks](V1.3.0-TENANT-ACCEPTANCE.md) before release. Require the GitHub check **SPFx production package** in branch protection to prevent future merges of unbuildable code. If CI cannot be configured, require a copy of a successful, warning-free `npm run package` log before accepting any handoff.

# v1.2.1 SharePoint pilot and upgrade

1. Record the currently deployed Tile Studio App Catalog version. Export configuration JSON from a representative page and save a page version for rollback.
2. On a connected Windows development workstation with Node.js 22.14–22.x, extract the ZIP and run `npm ci`, `npm test`, `npm run package`.
3. Confirm the package exists at `sharepoint/solution/imberon-tile-studio.sppkg`, read its version `1.2.1.0` and inspect requests (no new Graph API scopes expected).
4. Upload to the **existing** tenant App Catalog solution as an upgrade. Preserve the existing solution and component IDs; do not delete old web parts.
5. Open a **draft** page. Test old v1.1.1 layouts unchanged; toggle composition to Help, Service, Buttons, Health, News, Resource, and verify footer slots/icons/labels.
6. Add primary and secondary links. Test mouse, keyboard tab, Enter, external/new-tab behavior, invalid `javascript:` rejection, and that linked cards have no nested anchors.
7. Test missing category, badge, metadata, second link and status; confirm empty slots collapse and unknown health doesn't imply operational.
8. Test the native property pane while typing a partial URL, changing tabs, switching selected tiles, and resizing the SharePoint column. Close/reopen the panel, save, reload, and verify persistence.
9. Test per-tile overrides, reset to inherit, and a v1 export re-import. Test a page containing at least two different Tile Studio instances.
10. In a small pilot, connect a SharePoint list with new field mappings. Validate normal employee access, a denied access case, 404 list not found, and unconfigured fields.
11. If using shared presets, load a read-only list. Confirm that only authorized administrators can edit the list and that published pages are not remotely restyled without approval.
12. Validate keyboard navigation, WCAG contrast (including color overrides), narrow card overflow at 280/390/520 px, dark SharePoint sections, screen reader labels, and reduced-motion preference.
13. Publish only after the pilot is accepted, then monitor changes and page performance. Roll back using your App Catalog prior package and SharePoint page version if required.

**Do not upload the source ZIP as an SPFx deployment package.** Build the `.sppkg` locally first.

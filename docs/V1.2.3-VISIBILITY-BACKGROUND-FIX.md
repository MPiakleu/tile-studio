# Tile Studio v1.2.3 — Property Pane Visibility and Background Fix

## Changes

### Repeated SharePoint Visibility sections

The v1.2.2 web part cached the **entire** `IPropertyPaneConfiguration` and returned the same mutable pages/groups arrays on every call. SharePoint adds its own Visibility controls to the property pane. Repeated framework augmentation could therefore accumulate the native section in the cached structure.

v1.2.3 returns fresh property-pane configuration/page/group arrays on every request, while reusing the *same custom field object, callbacks, and key*. It retains out-of-order React host disposal protections, edit-draft state, focus recovery, and the SharePoint **native** Visibility control. We intentionally do **not** use the preview `disableVisibilityGroup` API or remove DOM nodes after SharePoint renders them.

Validation: regression tests simulate twelve repeated SharePoint augmentations and confirm only one custom group exists in each new configuration. Live SharePoint acceptance remains required to confirm that Microsoft's internal Visibility section is now rendered once.

### Card background colors

- Explicit `design.backgroundColor` and per-tile `tile.backgroundColor` now map to the card's rendered `backgroundColor` style, avoiding overrides by layout-specific CSS (including Minimal mode).
- The per-tile color takes priority over the section default. An unconfigured tile inherits the section default; with neither color configured, the existing SharePoint theme (and intentionally transparent Minimal links) remains in effect.
- The composed renderer now exposes the same `data-has-background` marker as the legacy renderer.
- Completed six/eight-digit hex values typed in the color editor immediately update the live preview; partial text is preserved until Enter/blur.
- The editor explains section-vs-tile precedence and displays a count when individual tiles have background overrides.

## SharePoint acceptance checks

1. Deploy `imberon-tile-studio.sppkg` built from v1.2.3 into a test site/draft page. The web-part GUID and solution GUID remain unchanged, enabling an in-place upgrade.
2. Open the native property pane. Change 15+ controls across Content, Style, Layout, Responsive and Presets, including typing hex colors. The SharePoint **Visibility** section should appear once only. Verify no editor freeze and that selected tab and current field remain stable.
3. Style → Card background (section default) → choose `#fff0cc`; verify all tiles without individual overrides change immediately. Navigate away and back to confirm saved state.
4. Content → Tile color overrides → select a tile → Tile background `#d1eaff`; verify only that tile changes. Clear the override; verify the global section background resumes.
5. Switch to Minimal layout and repeat both background tests; configured colors must stay visible. Clear both settings; Minimal should regain its original transparent default.
6. Test one layout using the classic renderer and one using the composed renderer, switching presets, narrow widths, and color/opacity variants.
7. Save/publish, reopen the page and property pane; confirm the colors and editor settings persist and only one native Visibility section appears.

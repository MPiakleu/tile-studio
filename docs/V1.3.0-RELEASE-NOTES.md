# Tile Studio 1.3.0 — Stabilization and Design Release

**Date:** 28 October 2026  
**Input:** Tile Studio 1.2.4 full source and the 13-item expert code/UX audit.  
**Output:** Source maintenance release (NOT a built or tenant-approved `.sppkg`).

## Breaking changes and compatibility

- **No change** to solution GUID, feature GUID, component GUID or schema version 2. Prior instances remain editable; the current project preserves custom content and saved presets.
- `cardInteraction` defaults to `auto`, preserving classic single-link behavior. Explicit action mode can be selected in Layout. Tiles with two destinations always use separate links.
- New installations default to tenant-only images; existing configurations without `imagePolicy` normalize to `any-https` to avoid silently dropping historical images. Administrators can tighten old instances explicitly.
- Newly created Tile Studio instances default to natural card height, while already saved heights are preserved.
- No new Microsoft Graph delegated permissions, external services, or application secrets.

## Known risks / go-no-go

1. **SPFx persistence and native visibility:** must verify in a real SharePoint editor after 1st, 10th, 30th edit, save/publish and hard reload. Unit tests cannot simulate framework-owned property-pane mutations and dirty-state behavior.
2. **Build / packaging:** npm dependencies could not download due to `EAI_AGAIN` DNS; therefore no full Heft build, lint, browser automation or `.sppkg` is certified or included.
3. **Browser a11y and visual:** reflow at 320–1440px, Windows high contrast, touch, keyboard focus, dark themes and reduced motion need actual browser and tenant validation.
4. **Commercial metadata:** vendor web, privacy/terms URLs remain blank; provide genuine URLs before resale/marketplace submission.
5. **Remaining code hygiene:** Editor tab orchestration is still substantial; a later refactor can split whole-tab panels once live functionality is verified. Do not broaden a high-risk release before pilot acceptance.

## Rollback

Save the previously deployed `.sppkg`, SharePoint page version and configuration export before upgrading. If the pilot fails, restore the previous App Catalog solution package and page version. Reapply/export designs created with v1.3.0 before rollback because older versions do not understand the new image-policy and interaction controls.

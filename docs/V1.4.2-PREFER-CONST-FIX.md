# Tile Studio v1.4.2 — ESLint `prefer-const` correction

## Confirmed failure in v1.4.1

The Windows `npm run package` command stopped at `npm run lint` with:

```text
src/webparts/tileStudio/services/listData.ts:138:15
warning 'handle' is never reassigned. Use 'const' instead (prefer-const)
```

The earlier v1.4.1 edit used `let handle` to avoid the `no-use-before-define` rule, but the native SPFx ESLint configuration correctly considers the variable eligible for `const`. Offline tests do not run ESLint and therefore did not catch it.

## Fix

In the retry-backoff Promise, schedule the timeout with `const handle = setTimeout(resolve, delay)` **before** defining the abort listener that uses `handle`. Preserve the preflight and post-listener abort checks so disposal during retry still rejects promptly. No ESLint rules were disabled or relaxed.

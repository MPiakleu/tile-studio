# Tile Studio v1.4.3 — Live preview and save/persistence repair

## Reported production symptoms

In v1.4.2, changing Tile Studio settings appeared to do nothing to the live SharePoint page. After clicking **Done editing** and then **Save and close**, the changes were missing. This is a serious functional regression. The project previously reported v1.2.x visibility-section duplication when repeatedly notifying SharePoint.

## Source-level root causes

1. `TileStudioWebPart.updateConfiguration` updated its local `properties.config`, then called `onPropertyPaneFieldChanged` **directly** instead of notifying the custom property pane's `changeCallback`. A direct invocation is not equivalent to asking the SharePoint property-pane host to record a changed field.
2. The same method removed its explicit `this.render()` call, assuming the SPFx lifecycle would repaint the web part. That assumption was not exercised by the tests, and the user's live SharePoint instance did not show edits in the preview.
3. The older automated tests checked the protected handler's call count and an in-memory property, not a custom-field notification plus a preview plus a save/reload. They permitted this regression.

These are confirmed source-level defects consistent with the user symptoms; **the precise Microsoft host behavior still requires staging tenant testing**.

## Fixes

- Notify the **currently mounted** custom field's callback with `('config', normalizedConfig, true)` before replacing the property bag's previous value. This preserves an opportunity for SharePoint to compare old/new values and mark the page modified.
- Always assign the normalized configuration to `this.properties.config` and repaint the web part when the SharePoint callback has not already rendered the **current** property-bag value. This also corrects hosts that repaint the previous configuration synchronously, without adding an unnecessary second render when they already painted the new value.
- Preserve the latest draft across property-pane host replacement and replay a pending notification when a valid new callback attaches. Keep normal protection against disposal of an old host after a new host appears.
- Preserve the existing component/solution IDs, stored config schema, layouts, presets, data access permissions, native property pane and panel identities.

### Visibility tradeoff

The native **Visibility** section remains enabled. An older tenant experienced duplicate Visibility sections when every edit invoked `changeCallback`; refreshing property-pane objects did not fully resolve that prior symptom. This release does **not** claim that this tenant-specific issue is solved. We intentionally did not add the preview-only `disableVisibilityGroup` API or modify SharePoint-owned DOM. **Stop and report if Visibility duplicates occur during the acceptance test; do not deploy broadly.**

## Automated checks performed

- **PASS:** 117/117 offline Node regression tests (`NODE_PATH=$(npm root -g) npm run test:offline`). Tests include consecutive edits, callback order and delivery, visible web part props, close/reopen, simulated save/deserialize, synchronous callback repaint, callback throwing and replacement, pending edits across host remounts, and the pre-existing functionality suites.
- **BLOCKED:** `npm ci`, failing with `EAI_AGAIN` resolving `registry.npmjs.org`. Because dependencies cannot be installed, the native strict ESLint, Heft production build, `.sppkg` package and real-browser testing could not be performed. A parsed TypeScript file and a mocked React render do **not** prove a real SharePoint build or functional tenant acceptance.
- **NOT RUN:** Browser/SharePoint tenant editing and page persistence. Requires a test page and an actual build.

## Required tenant acceptance (do not skip)

1. On a **test** SharePoint page, add the newly built v1.4.3 web part or upgrade a test instance. Hard-reload the page to avoid cached code. Confirm the version in the package.
2. Edit the page, open Tile Studio's native SharePoint properties, change **Section title** to a unique value. The tile collection section header should update **before you close the property pane**.
3. Change **Layout → gap/columns**, **Style → accent/background**, and a **manual tile title**. Confirm each change immediately appears on the page while editing. Verify the editor cursor stays where expected.
4. In the **same pane session**, make at least 20 more changes, including repeated slider/key input. Confirm no duplicated **Visibility** groups, no sluggishness, no disappearing input focus, and no stale value.
5. Make a **final, distinctive change**, click **Done editing**, then SharePoint **Save as draft / Republish** as appropriate. Exit edit mode. Hard reload and confirm **all** settings, particularly the final one, persist.
6. Reopen editing, make another change, and publish again. Check desktop, narrow columns and mobile. Check SharePoint list-connected mode using only accessible lists.
7. Repeat on a pre-existing v1.4.2 instance to verify configuration migration did not reset stored tiles and styles.

**Rollback:** Save a page version/export current Tile Studio configuration before upgrading. If preview, persistence or native Visibility fails, do not continue with production. Restore the prior App Catalog package and restore the page version/configuration if necessary. Existing configuration schema is unchanged.

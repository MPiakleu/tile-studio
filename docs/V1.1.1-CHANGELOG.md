# Tile Studio 1.1.1 — property-pane editing reliability

## Root cause

`onDispose` for a previous SharePoint custom property-pane host always cleared the shared edit callback, even when SharePoint had already mounted a replacement control. `updateConfiguration` discarded edits if the callback was missing. Also, recreating the configuration object on every `getPropertyPaneConfiguration` call could cause unnecessary remounts.

## Corrected

- Memoize the complete SharePoint property-pane configuration with an instance-specific field key.
- Track which host owns the current `changeCallback`; disposal of an outdated host cannot invalidate the current one.
- Update the web-part property bag before notifying SharePoint, retain edits during a temporary callback gap, and replay the latest pending update when the new control attaches.
- Preserve the selected tab, current tile, and editor search during host replacement; restore keyboard focus/selection when safely possible.
- Maintain native SharePoint editing, all existing layout and tile settings, and unchanged configuration schema and solution/component GUIDs.
- Add regression coverage for host replacement, stale disposal, repeat onRender and callback absence.

## Deployment

Requires Node 22.14+ and `npm ci && npm test && npm run package`. The original 1.0/1.1 `.sppkg` is **not** included. The SPFx production build and live-tenant save/reload test were not available in this execution environment. Before organization-wide rollout, validate in a draft SharePoint page: type continuously, switch tabs, edit many tiles, change sliders, close/reopen, save/reload, and edit multiple Tile Studio instances.
